# Documentation conventions

Rules every note in this vault follows. Two of them are enforced in CI; the
rest are review discipline. Back to [Documentation home](index.md).

## Links

Use relative markdown links only, always including the `.md` extension:

```markdown
[Auth design](../adr/0007-auth.md)
```

Do not use Obsidian's double-square-bracket wikilinks or embeds. They resolve
only inside Obsidian, cannot be verified by a script, and silently
mis-resolve between files that share a basename.

## Filenames

Lowercase kebab-case, no spaces. This keeps links free of `%20` escapes and
keeps paths safe for shells and CI.

## Moving and renaming

**Never rename or move a file in this vault.** Propose the change and let a
human perform it inside Obsidian, so backlinks are rewritten automatically.
Creating new files and editing existing ones is fine.

## Frontmatter

Every new note requires three keys:

```yaml
---
title: Human-readable title
status: draft | active | superseded
updated: YYYY-MM-DD
---
```

When editing an existing note, preserve every key already present. Never
rewrite the YAML block wholesale.

## No query blocks

No Dataview, Templater, or other plugin query syntax. Notes must render
correctly as static markdown in a pull request diff and on the repository web
UI, where no plugin is available to evaluate them.

## Provenance

Notes generated by tooling or by an assistant belong in `generated/`.
Do not edit anything under `adr/` or `decisions/` without asking first —
those record decisions a human made, and rewriting them loses that history.

## Enforcement

`.github/workflows/docs.yml` runs two checks on every pull request touching
this vault. They catch different failures and neither replaces the other:

1. **A grep guard** rejecting wikilink syntax. This is what makes the
   convention enforceable — a link checker does not recognise wikilinks as
   links at all, so a wikilink would pass link checking silently.
2. **lychee** in `--offline` mode, proving every relative path actually
   resolves. Offline mode skips network URLs, so the check is fast and never
   flakes on someone else's dead domain.

Run both locally before pushing:

```bash
./scripts/check-docs.sh
```

The script needs [lychee](https://lychee.cli.rs) for the second check
(`brew install lychee`). It reports the check as skipped rather than failing
when lychee is absent, so CI remains the authority.
